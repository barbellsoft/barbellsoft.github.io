Mapped network drive shows a red X: how to reconnect it

You open File Explorer and your Z: drive has a red X on it. Double-click it and Windows thinks for a while, then gives up with something like "An error occurred while reconnecting Z:" or "The network path was not found". It worked yesterday.

A mapped drive is a drive letter that points to a folder on a NAS or server. The files aren't on your PC. So the red X is about the connection: Windows couldn't reach that folder the last time it tried. By itself it doesn't tell you anything has happened to the files.

What is going on

When you sign in, Windows tries to reconnect your mapped drives. If that attempt fails, the letter stays in File Explorer with a red X on it.

The harmless version of this is timing. Windows tried before the network was ready, because the Wi-Fi connected a few seconds later or the VPN wasn't running yet. In that case the drive often opens the moment you double-click it.

The less harmless versions take more work to sort out:

  • The NAS or server is switched off or asleep.
  • The PC is on a different network from the server.
  • The server was renamed or was given a new address.
  • The shared folder was renamed or removed.
  • Your account lost its permission to the folder.
  • Your password changed, and the password Windows saved no longer works.

Safe things to try first

None of these steps touch the files on the server.

Double-click the drive, then press F5

If the network came up late, this may be all you need.

Check the network

Make sure the NAS is on and the PC is on the same network as the server. If the server is at your office and you're working from home, connect your VPN first.

Open the folder by its address

File Explorer shows the server beside the drive name, for example documents (\\nas) (Z:). Type the full address in the File Explorer address bar, for example \\nas\documents, and press Enter. If the folder opens, the server is fine and it's the drive letter that needs reconnecting. If it doesn't, the problem is further along: the server, the network or your sign-in.

Map the drive again

Write down the address first. Right-click the drive and choose Disconnect. Then right-click This PC and choose Map network drive. On Windows 11, either command may be under Show more options. Pick the same letter, type the address and tick Reconnect at sign-in. Disconnecting removes the letter from this PC and leaves the files on the server alone.

Clear an old saved password

If you changed your password recently, open Control Panel, then Credential Manager, then Windows Credentials. Remove the entry for that server, then open the folder again so Windows asks you to sign in.

Reconnecting the drive with ReviveFix

ReviveFix is a free tool for Windows 10 or 11 (64-bit) that checks your network drives, reconnects them when it can and tells you which step failed when it can't. It's one exe file of about 8 MB with no installation. It's still a beta.

1. Download and start it

Get it from the download page. ReviveFix isn't code-signed yet, so SmartScreen may say it doesn't recognize the app. The download page lists the file's SHA-256. Check it in PowerShell with Get-FileHash .\ReviveFix.exe -Algorithm SHA256. If it matches, choose More info, then Run anyway.

ReviveFix starts without administrator rights. If a fix needs them, Windows asks once. Choose No and nothing changes, and that item stays marked ⚠.

2. Click Find and fix problems

You don't need to know what's broken. Drives already connected to the PC, like your Z: drive, are always checked. If you also have a folder you open by its address, type that address in the box first, for example \\nas\documents, and then click Find and fix problems.

3. Read the marks

Each line gets one of four marks:

  • ✓ means it works normally.
  • ✔ means it was broken and ReviveFix fixed it.
  • ⚠ means it can be fixed after you confirm. Click Fix.
  • ✗ means it can't be fixed from this PC.

For a drive with a red X, ReviveFix asks Windows to reconnect it with the address and account Windows remembers. If the server answers, the drive opens again and its line shows ✔. If not, ReviveFix tells you which step failed: the server name, the network connection, the shared folder or the sign-in.

When the saved password is the problem, ReviveFix removes only the saved password for that server and opens the folder. Windows then asks you in its own sign-in window. ReviveFix never asks for or reads your password, and it doesn't see what you type. It doesn't send anything over the internet either.

If it still won't open

What to do next depends on the reason ReviveFix gives.

The server name can't be found

Check the spelling of the address. If it's correct, the server may have been renamed, so ask whoever manages it for the current name.

The server can't be reached

Go back to the basics: is the NAS on, is the PC on the right network, is the VPN connected?

The shared folder doesn't exist

It may have been renamed, moved or removed on the server. Only the person who manages the server can tell you the new address.

You don't have permission

This is set on the server, so the NAS administrator has to give your account access.

The saved password no longer works

After ReviveFix removes it, sign in when Windows asks. If your new password is refused too, ask the administrator to check your account.

An old NAS needs SMB1 or guest access

ReviveFix won't turn these on, because they make the whole PC easier to attack. It explains the problem instead. I wouldn't turn them on by hand to get a drive back either. The better fix belongs on the NAS.

It can't be fixed from this PC

ReviveFix can't fix the NAS itself, and it doesn't change settings your company manages. On a ✗ line, click Copy for IT and send the text to whoever looks after the NAS. Copy diagnosis copies the results, recent fixes and your Windows version to paste into an email or chat. It includes server, drive and printer names but no passwords.
