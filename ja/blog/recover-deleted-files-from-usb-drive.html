USBメモリから削除したファイルを復元する方法

USB メモリからフォルダーを削除し、元に戻そうとごみ箱を開いたら、そこにない。これは正常な動作です。Windows は USB メモリから削除したファイルをごみ箱に送りません。どのドライブで Shift+Delete を押した場合と同じように、すぐに削除されます。

だからといって、ファイルが消えたわけではありません。ほとんどの場合ファイルはまだドライブに残っていて、次に何をするかで、どれだけ取り戻せるかが決まります。

ファイルを削除すると実際に何が起きるか

ドライブには、どのファイルがどこにどんな名前で保存されているかを記録した索引、つまりファイルシステムがあります。ファイルを削除しても、データそのものはたいていドライブに残ります。消えるのはそのデータを指している索引の項目だけで、だからこそ復元ができるのです。

問題は、そのファイルが占めていた領域が空き領域として扱われるようになることです。ドライブに新しいファイルを保存すると、Windows がちょうど古いデータの上に書き込むことがあり、そうなると古いデータは復元できません。削除したあとにドライブへ書き込む量が多いほど、取り戻せる量は少なくなります。

今すぐすること

ファイルを安全な場所に移すまでは、ドライブに何も保存したりコピーしたりしないでください。復元用のプログラムや、復元したファイルも同じです。フォーマットもしないでください。Windows にスキャンして修復するか聞かれても、「はい」をクリックしないでください。

ドライブから読み取るだけなら問題ありません。まだ作業を始められない場合は、ドライブを取り出して抜いたままにしておき、その間に何も書き込まれないようにしてください。

ReviveUSB でファイルを取り戻す

ReviveUSB は、決まった順番で作業する無料の Windows プログラムです。まずドライブ全体をイメージファイルにコピーし、そのコピーからファイルを復元します。バックアップと復元は、ドライブを読み取るだけです。Windows 10 または 11 (64 ビット) で動き、インストール不要の exe ファイル 1 つで、ディスクを直接読み取るため管理者権限が必要です。

イメージはドライブ全体のコピーなので、USB メモリと同じ大きさの空き容量が別のドライブに必要です。128 GB のドライブなら 128 GB の空きが要ります。復元したファイルを置く場所も必要で、これは USB メモリ以外ならどのドライブでもかまいません。

ReviveUSB はまだコード署名されていないため、Windows SmartScreen やウイルス対策ソフトが警告することがあります。ダウンロードページにファイルの SHA-256 が載っています。PowerShell で Get-FileHash .\ReviveUSB.exe -Algorithm SHA256 を実行して確認し、値が一致したら 詳細情報、続けて 実行 を選んでください。ダウンロードしたファイルは USB メモリではなく PC に保存してください。

1. ドライブを選ぶ

ReviveUSB.exe を実行し、管理者権限を許可します。ウィンドウの上部に 管理者権限: オン と表示されているはずです。オフになっている場合は、管理者として再起動 をクリックします。USB メモリを接続して 更新 をクリックし、一覧でドライブをクリックします。一覧に出るのは USB ディスクだけなので、内蔵ディスクが紛れ込むことはありません。

2. イメージにバックアップする

イメージにバックアップ をクリックし、空き容量が十分ある別のドライブにイメージを保存します。提案される名前は diskN.img で、N はディスク番号です。保存先に USB メモリ自体を選ぶと、ReviveUSB はそれを拒否して別のドライブを選ぶよう求めます。そこに保存すると、取り戻したいファイルを上書きしてしまうおそれがあるからです。

ウィンドウはいつでも閉じられます。後で続けるには、プログラムをもう一度起動し、同じドライブを選んで イメージにバックアップ をクリックし、同じファイルを選んで、置き換えるか Windows に聞かれたら「はい」と答えます。ログに イメージ作成を再開 と表示され、止まったところからコピーが続きます。

ここから先はイメージを使って作業し、USB メモリを再び読むことはありません。

3. ファイル復元(名前・パス)

ファイル復元(名前・パス) をクリックします。一覧でディスクが選ばれているので、ReviveUSB はまず、そのディスクを直接読むかどうかを尋ねます。いいえ をクリックして .img ファイルを選んでください。イメージのほうが適しています。次に、正常なドライブ上に結果を保存するフォルダーを選びます。

この方法は NTFS、FAT32、exFAT を読み取ります。見つけられたファイルはすべて名前とフォルダーごとコピーし、削除されたファイルや、削除されたフォルダーの中にあったファイルも含まれます。現在のファイルと削除されたファイルの両方が見つかった場合、削除されたものは別の _deleted_files フォルダーに入るので、古いコピーが現在のファイルと並ぶことはありません。まず確認すべきなのはこのフォルダーです。

保存先のフォルダーには、ファイルと同じだけの空き容量が必要です。足りない場合は、何かが始まる前にログで警告されます。

FAT32 のドライブでは、一部のファイルについて「中身が違う可能性があります」とログに表示されることがあります。Windows がそれらを削除したときに、開始位置の情報の一部を消したためです。.bin のような形式には正しい位置を見分けるシグネチャがありません。そうしたファイルは、使う前に開いて確認してください。

4. 何も戻らなければシグネチャで復元する

名前・パスでの復元で何も見つからない場合や、ファイルシステムを認識できないと表示された場合は、同じイメージで ファイル復元(シグネチャ) を実行します。中身からファイルを探す方法なので、ファイルシステムがなくなっていても使えます。対象は JPEG、PNG、GIF、BMP、PDF、ZIP のファイルと、MP4、MOV、3GP、M4A、HEIC です。スマートフォンやドライブレコーダーの動画、iPhone の写真がこれに当たります。

この方法では名前が失われます。ファイルは jpg_00001_@... のような通し番号付きで戻ります。docx、xlsx、pptx のような Office のファイルは中身が ZIP ファイルなので、.zip という名前で届きます。正しい拡張子に名前を変えてください。

ドライブの修復は不要

ファイルを削除しても、ドライブは壊れません。修復用のボタン(検査(chkdsk)、フォーマット、完全再構築)は Windows が開けないドライブのためのもので、フォーマット と 完全再構築 はデータを消去します。ここでは使わないでください。

復元したファイルを PC で開いて確認します。必要なものがそろったら、いつもの方法で USB メモリにコピーし直して使い続けてかまいませんが、PC にもコピーを残しておいてください。そのあとは、イメージファイルと、その隣にある進行状況のファイル(たとえば disk2.img と disk2.img.state.json)を削除してかまいません。

うまくいかないとき

復元したファイルが開けない場合は、断片化していて先頭部分しか戻らなかった可能性があります。イメージに対して両方の復元ボタンを試してください。

バックアップがとても遅い場合、ReviveUSB はすでに不良領域を飛ばしているので、原因はたいていドライブか接続です。ハブを使わずに PC 背面の USB 3.0 ポートにドライブを直接挿す、ケーブルを替える、別の PC を試す、といった方法があります。同じイメージファイルにもう一度バックアップすれば、止まったところから続きます。時間がない場合は、途中でプログラムを閉じ、そこまでできたイメージで ファイル復元(シグネチャ) を実行してください。コピーできた部分からファイルを復元します。

何も戻らない場合は、削除したファイルの上に新しいデータが書き込まれた可能性があります。上書きされたデータはどんなソフトウェアでも復元できず、フラッシュチップが壊れてしまったドライブのデータも同じです。その場合に残る手段は、データ復旧の専門業者です。

各ボタンの説明はマニュアルに、復元についてよくある疑問はよくある質問にあります。
