ReviveUSB 사용 설명서

ReviveUSB는 고장 난 USB 메모리나 외장하드에서 파일을 되살리고, 원하면 드라이브를 고쳐 다시 쓸 수 있게 해 주는 프로그램입니다. 모든 작업은 창 하나에서 합니다. 디스크를 고른 뒤 버튼을 누르면 됩니다. 이 설명서를 처음부터 차례대로 따라 하세요.

0. 빠른 시작

  1. ReviveUSB.exe 를 실행하고, Windows가 관리자 권한을 물으면 허용합니다.
  2. 새로고침을 누른 뒤 디스크 목록에서 USB 드라이브를 클릭합니다.
  3. 이미지 백업을 누르고, 빈 공간이 넉넉한 다른 드라이브에 이미지를 저장합니다.
  4. 파일 복구(이름·경로)를 누르고 이미지를 고른 다음, 멀쩡한 드라이브의 폴더를 지정합니다. 아무것도 나오지 않으면 파일 복구(시그니처)로 똑같이 해 봅니다.
  5. 파일을 모두 되찾은 다음에만 수리 버튼 중 하나로 드라이브를 다시 쓸 수 있게 만듭니다.

꼭 지킬 규칙은 하나입니다. 데이터를 되찾고 싶다면 고장 난 드라이브에 새로 아무것도 저장하지 마세요. 먼저 이미지를 만들고, 그 이미지에서 복구합니다.

데이터는 필요 없고 드라이브만 다시 쓰고 싶다면 3단계와 4단계는 건너뜁니다. 자세한 내용은 7장에 있습니다.

1. 이 프로그램이 하는 일

드라이브가 다음 중 하나에 해당할 때 씁니다.

  • 실수로 파일을 지웠습니다.
  • 드라이브를 꽂으면 Windows가 "사용하려면 먼저 디스크를 포맷해야 합니다"라고 묻습니다. 파일시스템이 망가진 상태이며 RAW로 표시됩니다.
  • 파티션이 망가져서 용량이 큰 드라이브가 작은 RAW 조각으로 보이거나 드라이브 문자가 없습니다.
  • 드라이브는 인식되는데 파일이 보이지 않습니다.

목표는 두 가지이고, 프로그램 하나로 둘 다 처리합니다.

목표 뜻 버튼
데이터 되찾기 지워졌거나 보이지 않는 파일을 복구합니다 이미지 백업 후 파일 복구 버튼 중 하나
드라이브 되살리기 드라이브를 다시 포맷해 쓸 수 있게 합니다 검사(chkdsk), 포맷, 완전 복구(rebuild)

순서는 정해져 있습니다. 데이터를 먼저 복구하고, 드라이브 수리는 그다음에 합니다. 수리부터 하면 데이터가 영영 사라집니다.

2. 시작하기 전에 읽을 안전 수칙

복구를 망치는 원인은 고장 난 드라이브에 무언가를 쓰는 일입니다. 이 프로그램을 실행하는 것은 괜찮습니다. 백업과 복구는 드라이브를 읽기만 하기 때문입니다.

이유는 이렇습니다. 파일을 지워도 보통 데이터 자체는 드라이브에 남아 있습니다. 그 파일을 가리키는 색인 항목만 지워지며, 복구가 가능한 이유도 바로 이것입니다. 이 상태에서 드라이브에 새 파일을 저장하면, 시스템은 예전 데이터가 있는 자리를 빈 공간으로 보고 새 파일을 그 위에 바로 쓸 수 있습니다. 그렇게 되면 예전 데이터는 되찾을 수 없습니다.

복구하기 전에는 다음을 하지 마세요.

  • 드라이브에 새 파일을 저장하거나 복사하기
  • Windows에서든 수리 버튼으로든 드라이브 포맷하기
  • Windows가 드라이브를 검사하고 복구하겠다고 할 때 예 누르기

다음 버튼은 읽기만 하므로 안전합니다. 새로고침, 건강검진, 이미지 백업, 그리고 두 파일 복구 버튼입니다.

4. 프로그램 시작하기

4.1 내려받고 파일 확인하기

다운로드 페이지에서 ReviveUSB.exe 를 내려받습니다. 이 파일은 아직 코드 서명이 되어 있지 않아서 Windows SmartScreen이나 백신이 경고할 수 있습니다. 실행하기 전에 파일이 다운로드 페이지에 적힌 SHA-256과 같은지 확인하세요. PowerShell에서 다음을 실행합니다.

Get-FileHash .\ReviveUSB.exe -Algorithm SHA256

해시가 같은데 SmartScreen이 뜨면 추가 정보를 누른 뒤 실행을 누릅니다.

4.2 관리자 권한

디스크를 날것 그대로 읽으려면 관리자 권한이 있어야 하므로, 프로그램은 시작할 때 관리자 권한을 요청합니다. 허용하세요. 그러면 창 위쪽에 관리자 권한: 켜짐이 표시됩니다. 꺼짐으로 나오면 관리자 권한으로 다시 실행을 누릅니다.

창 맨 위 도움말(H) 메뉴에서 ReviveUSB 도움말(H) 항목을 고르거나 F1 키를 누르면 이 설명서가 열립니다. 설명서는 프로그램 안에 들어 있어서 인터넷이 안 돼도 브라우저로 열립니다. 버전은 이 프로그램은...(A)(Ctrl+F1)에서 봅니다. ReviveUSB 홈페이지(W) 는 barbellsoft.com을, 업데이트 확인(U) 은 최신 버전이 있는 다운로드 페이지를 엽니다. 같은 메뉴의 후원 항목과 창 오른쪽 위 ♥ 후원 단추는 Buy Me a Coffee 페이지를 브라우저로 엽니다. ReviveUSB는 무료이고 후원은 자유이며, 프로그램이 결제를 다루지는 않습니다. 파일을 되찾았거나 되돌려 넣기를 마치면 로그 끝에 후원 주소가 한 줄 나옵니다.

목록에는 USB 디스크만 나옵니다. 내장 디스크는 내장 디스크도 보기(주의)에 체크하지 않는 한 숨겨집니다. 무엇을 하는지 정확히 알 때가 아니면 체크하지 마세요.

작업이 도는 동안에는 작업 버튼이 회색으로 바뀌고, 진행 막대와 로그가 계속 갱신됩니다. 중지 버튼은 없습니다. 백업을 멈추려면 창을 닫으세요. 나중에 이어 하는 방법은 5장에 있습니다.

5. 다섯 단계로 드라이브 복구하기

1단계. 드라이브 고르기

드라이브를 꽂고 새로고침을 누릅니다. 목록에서 내 드라이브를 클릭합니다. 로그에 어떤 디스크를 골랐는지 나옵니다. 예를 들면 디스크 2 선택: SanDisk Ultra 입니다.

파일시스템 열을 보세요. RAW라면 파일시스템이 망가진 것입니다.

이때 건강검진을 눌러 봐도 됩니다. 드라이브 상태를 보여 주고, 드라이브가 제공한다면 마모도나 정정할 수 없는 읽기 오류 같은 SMART 카운터도 보여 줍니다. USB 드라이브 중에는 SMART 정보를 넘겨주지 않는 것이 많은데, 그때는 로그에 그렇다고 나옵니다.

2단계. 이미지로 백업하기

이미지 백업을 누릅니다. 빈 공간이 넉넉한 다른 드라이브에서 이미지를 저장할 곳을 고릅니다. 기본으로 제안하는 이름은 diskN.img 이고, N은 디스크 번호입니다.

원본 드라이브는 읽기만 합니다. 불량 구간은 빠르게 건너뛰므로 복사가 멈추지 않고 계속 진행됩니다. 진행 막대에 퍼센트와 복사한 양이 나옵니다.

읽지 못한 구간이 있으면, 그 구간을 섹터 단위로 다시 읽을지 묻습니다. 재시도하면 데이터를 더 살릴 수 있지만, 많이 망가진 드라이브에서는 오래 걸릴 수 있습니다. 재시도 중에 창을 닫았다면, 나중에 같은 파일로 다시 백업하면 재시도를 이어서 합니다. 다 끝난 이미지로 다시 백업해도 드라이브 전체를 다시 읽지는 않고, 읽지 못한 구간만 재시도할지 묻습니다. 처음부터 다시 하려면 새 파일 이름을 고르세요.

복구하려는 드라이브 안의 위치를 고르면 프로그램이 거부하고 다른 드라이브를 고르라고 합니다. 거기에 저장하면 되찾으려는 파일을 덮어쓸 수 있기 때문입니다.

언제든 창을 닫아 멈출 수 있습니다. 진행 상황은 2초마다 저장됩니다. 이어서 하려면 프로그램을 다시 실행하고, 같은 드라이브를 고른 뒤 이미지 백업을 누르고 같은 파일을 고릅니다. Windows가 파일을 바꿀지 물으면 예를 누릅니다. 그러면 로그에 이미지 이어받기 가 나오고 멈춘 곳부터 복사를 이어 갑니다. 프로그램은 같은 드라이브인지 확인합니다. 파일이 다른 드라이브의 것이거나 드라이브 크기가 달라졌으면, 예전 사본을 섞거나 덮어쓰지 않고 멈춥니다. 이럴 때는 새 파일 이름을 고르세요.

3단계. 이미지에서 파일 복구하기

버튼이 두 개 있습니다. 먼저 파일 복구(이름·경로)를 써 보고, 아무것도 찾지 못하면 파일 복구(시그니처)를 씁니다.

  1. 버튼을 누릅니다.
  2. 이미지 파일(.img)을 고릅니다.
  3. 복구한 파일을 저장할 폴더를 멀쩡한 드라이브에서 고릅니다. 복구하려는 드라이브 안의 폴더는 거부됩니다. 드라이브에 파티션이 여러 개 있으면 파티션마다 volume2_exfat 같은 하위 폴더에 따로 저장됩니다.

이름·경로 방식은 지운 파일만이 아니라 찾을 수 있는 파일을 모두 복사합니다. Windows가 드라이브에 "액세스할 수 없습니다"라고 하거나 포맷하라고 할 때 바로 이 방식을 쓰면 됩니다. 이럴 때 파일은 대개 그대로 남아 있고, 이름까지 붙은 채로 돌아옵니다. 현재 파일과 지운 파일이 함께 나오면 지운 파일은 _deleted_files 폴더에 따로 넣습니다. 그래서 예전 사본이 현재 파일 옆에 섞이지 않습니다. 저장할 폴더에는 파일 크기만큼 빈 공간이 있어야 합니다. 공간이 모자라면 시작하기 전에 로그에 경고가 나옵니다. Windows에서 지운 FAT32 드라이브라면 로그에 "내용이 틀릴 수 있다"는 파일 목록이 나올 수 있습니다. Windows가 시작 위치의 일부를 지웠는데, .bin처럼 확인할 지문이 없는 형식은 맞는 자리를 가릴 수 없기 때문입니다. 그 파일들은 믿고 쓰기 전에 열어 보세요.

파일 복구(이름·경로) 파일 복구(시그니처)
되찾는 것 파일 이름, 폴더 경로, 내용 내용만. 이름은 jpg_00001_@... 처럼 일련번호로 붙습니다
지원 대상 NTFS, FAT32, exFAT 어떤 드라이브든, 파일시스템이 사라져도 됩니다
잘 맞는 경우 Windows가 드라이브를 열지 못해도 파일시스템은 아직 읽을 수 있는 경우 파일시스템 자체가 망가진 경우
순서 먼저 시도 앞의 방법으로 아무것도 못 찾았을 때

드라이브가 RAW로 보여도 이름·경로 방식을 먼저 시도하세요. Windows는 파일시스템을 마운트하지 못하면 그 안의 값이 하나만 틀려도 RAW로 표시합니다. 이럴 때도 프로그램은 파일시스템을 읽어 내서 파일을 이름째로 되살리는 경우가 많습니다. 파일시스템을 인식하지 못했다고 나오거나 아무것도 찾지 못하면 시그니처 방식을 쓰세요.

시그니처 방식은 JPEG, PNG, GIF, BMP, PDF, ZIP 파일과 MP4, MOV, 3GP, M4A, HEIC 파일(휴대폰·블랙박스 동영상, iPhone 사진)을 찾습니다. docx, xlsx, pptx 같은 Office 파일은 속이 ZIP 파일이라서 .zip 이름으로 복구됩니다. 알맞은 확장자로 이름을 바꿔 주세요. 끝부분이 기록되지 않은 동영상(녹화가 도중에 끊겼거나 드라이브가 데이터를 잃은 경우)은 남아 있는 데까지 저장하지만, 끝부분이 없어서 대부분의 플레이어에서 재생되지 않습니다.

목록에서 디스크를 골라 두었다면, 프로그램이 먼저 그 디스크에서 바로 읽을지 묻습니다. 이미지 파일을 고르려면 아니요, 디스크를 직접 읽으려면 예를 누르세요. 디스크를 직접 읽으려면 관리자 권한이 필요하고, 고장 나는 중인 드라이브에는 더 위험하므로 이미지를 쓰는 편이 낫습니다.

4단계. 드라이브 수리하기 (복구를 마친 뒤에만)

드라이브를 고르고 수리 버튼 중 하나를 씁니다. 어떤 버튼을 고를지는 7장에 있습니다. 포맷과 완전 복구(rebuild)는 데이터를 지우므로, 프로그램이 확인 문구를 정확히 입력하라고 합니다. 예를 들면 FORMAT E 입니다. 이 버튼을 쓰기 전에 모든 파일을 복구했는지 꼭 확인하세요.

수리 버튼(검사(chkdsk), 포맷, 완전 복구(rebuild))은 드라이브에 쓰기 전에 먼저 읽기만 해서 드라이브를 점검합니다. 컨트롤러가 고장 나 가는 징후가 보이면 수리하지 않고 그 이유를 로그에 적습니다. 드라이브가 읽기에 응답하지 않거나 크기가 0으로 나올 때, 드라이브 일부를 읽지 못했을 때가 그런 징후입니다. FAT32 드라이브라면 파일시스템에 적힌 크기가 실제 드라이브보다 큰지, 파일 위치표(FAT)의 두 사본이 여러 곳에서 다른지, 파일이 있다는 자리의 절반 이상이 빈 값으로 읽히는지도 봅니다. 이때는 수리를 강행하는 방법이 없습니다. 수리는 드라이브에 많이 쓰는데, 고장 나 가는 드라이브는 큰 쓰기를 하다가 아예 멈출 수 있기 때문입니다. 2·3단계로 파일을 되찾은 뒤 드라이브를 바꾸세요. 파일시스템을 알아보지 못해 RAW로만 보이는 드라이브는 막지 않습니다. 데이터 없이 바로 수리할 때(7장)도 같은 점검을 합니다.

5단계. 파일 되돌려 넣기 (수리를 마친 뒤)

전체 순서는 이렇습니다. 데이터를 복구하고, 복구한 파일을 PC에 보관하고, 드라이브를 수리한 뒤, 수리한 드라이브에 파일을 되돌려 넣습니다. 이 단계가 그 마지막입니다. 드라이브를 다시 믿고 쓰기 전에 데이터를 제대로 저장하는지도 여기서 확인합니다.

포맷이나 완전 복구(rebuild)가 끝나면 로그에 다음 할 일이 나옵니다. 새로고침을 누르고, 드라이브 시험을 한 다음 파일 되돌려 넣기를 하라는 안내입니다. 두 버튼은 수리 뒤: 줄에 있고, 선택한 디스크의 드라이브 문자에 작업합니다. 관리자 권한은 필요 없습니다.

  1. 새로고침을 누르고 수리한 드라이브를 고릅니다. 드라이브 문자가 바뀌었을 수 있습니다.
  2. 드라이브 시험을 누릅니다. 빈 공간 전체를 시험하려면 예, 1 GB만 빠르게 시험하려면 아니요를 누릅니다(취소를 누르면 아무것도 하지 않습니다). 전체 시험은 오래 걸리지만, 용량을 속이는 드라이브는 빠른 시험으로는 드러나지 않고 전체 시험에서 드러납니다. 프로그램은 드라이브에 _revive_test 폴더를 만들어 시험 데이터를 쓰고, Windows 캐시를 거치지 않고 다시 읽어 비교한 뒤 그 폴더를 지웁니다. 예전 시험이 중간에 끊겨 남은 폴더가 있으면 그것도 지웁니다. 쓰다가 드라이브가 꽉 차면 거기서 쓰기를 멈추고 그때까지 쓴 데이터만 확인합니다.
  3. 로그에서 결과를 봅니다. 통과하면 얼마만큼 쓰고 다시 읽었는데 오류가 없었다고 나옵니다. 실패하면 얼마만큼이 제대로 읽히지 않았는지 나오니 드라이브를 바꾸세요. 나중에 쓴 데이터가 앞에 쓴 데이터 자리에서 읽혔다면, 이 드라이브가 실제로는 표시된 용량보다 적게 담는 것으로 보인다고 대략적인 용량과 함께 로그에 나옵니다. 용량을 속이는 드라이브이니 파일을 넣지 마세요. 시험 도중 드라이브가 응답을 멈추면, 얼마만큼 처리한 뒤에 멈췄는지와 함께 이 드라이브에는 데이터를 믿고 맡길 수 없다고 로그에 나옵니다. 파일을 넣지 말고 드라이브를 바꾸세요.
  4. 파일 되돌려 넣기를 누르고, 복구한 파일이 들어 있는 PC의 폴더를 고릅니다. 같은 드라이브에 있는 폴더는 받지 않습니다. 드라이브의 빈 공간이 모자라면 아무것도 쓰기 전에 알려 줍니다. 폴더 구조는 그대로 두고 모든 파일을 복사하는데, 맨 위에 있는 System Volume Information 과 $RECYCLE.BIN 폴더만 뺍니다. 이 두 폴더는 Windows가 알아서 다시 만듭니다.
  5. 복사가 끝나면 프로그램이 모든 파일을 드라이브에서 다시 읽고(역시 캐시를 거치지 않습니다) 원본과 SHA-256 값을 비교합니다. 모두 같으면 로그에 그렇게 나옵니다. 다르게 읽힌 파일이 있으면 그 목록과 함께, 드라이브가 데이터를 제대로 저장하지 못한다는 말이 나옵니다. 그 드라이브에는 중요한 파일을 두지 마세요.

복사가 잘 끝나도 PC에 있는 복구 파일은 지우지 말고 사본으로 남겨 두세요.

6. 버튼 설명

새로고침 연결된 USB 드라이브를 보여 줍니다(체크 상자를 켜면 내장 디스크도) 아니요 아니요

이미지 백업 드라이브 전체를 이미지 파일로 복사합니다. 불량 구간은 건너뛰고, 섹터 단위 재시도를 제안하며, 예전 사본을 이어서 복사합니다 아니요 예

7. 데이터가 필요 없을 때 드라이브 수리하기

파일은 필요 없고 고장 난 USB 드라이브나 외장 디스크를 다시 쓰고 싶기만 하다면, 백업과 복구 단계를 건너뛰고 바로 수리합니다.

7.1 먼저 진단하기

새로고침을 누르고 드라이브를 고른 뒤 목록과 로그를 봅니다. WD 외장 드라이브의 실제 사례를 보면, 목록에 3.6 TB, 상태 Healthy/Online 이 나왔고 드라이브 문자 없는 200 MB짜리 RAW 조각 하나만 보였습니다.

읽는 법은 이렇습니다. 상태가 Healthy/Online 이면 하드웨어는 정상이고 파티션 구조만 망가진 것입니다. 이런 경우는 대개 소프트웨어로 고칠 수 있습니다. 큰 드라이브에 작은 RAW 조각만 보이거나 드라이브 문자가 없다면, 주 파티션이 사라진 것입니다.

7.2 수리 방법 고르기 (약한 것부터 강한 것 순)

증상 버튼 하는 일
드라이브 문자는 있고, 파일이 깨지거나 읽기 오류가 남 검사(chkdsk) 파일시스템 오류를 고치고 데이터는 유지합니다
드라이브 문자는 있고, 깨끗이 지우고 싶음 포맷 볼륨만 다시 포맷합니다
RAW, 드라이브 문자 없음, 파티션 손상 완전 복구(rebuild) 디스크 전체를 지우고 다시 만듭니다. 보통 이것으로 해결됩니다

검사(chkdsk)와 포맷은 드라이브 문자가 있어야 합니다. 드라이브 문자가 없으면 프로그램이 완전 복구(rebuild)를 쓰라고 안내합니다. 또 RAW 드라이브는 고칠 파일시스템이 남아 있지 않아서 chkdsk로 고칠 수 없습니다.

7.3 RAW 드라이브 되살리기

가장 흔한 경우입니다. 드라이브를 고르고 완전 복구(rebuild)를 누른 뒤, 입력하라고 하면 ERASE DISK 2 를 입력합니다(숫자는 내 디스크 번호). 보통 몇 초에서 1분쯤 걸립니다. 끝나면 드라이브에 새 드라이브 문자가 붙습니다. 파일을 맡기기 전에 새로고침을 누르고 드라이브를 골라 드라이브 시험을 해 보세요. 결과를 읽는 법과 파일을 되돌려 넣는 법은 5장의 5단계에 있습니다.

새 파일시스템은 NTFS이며 Windows에서 읽고 쓸 수 있습니다. Mac이나 다른 기기에서 써야 한다면, 그 기기나 Windows 자체 포맷 창으로 나중에 다시 포맷하세요.

7.4 정리하기

예전에 만든 이미지가 더는 필요 없으면 이미지 파일과 그 옆의 진행 파일을 지웁니다. 예를 들면 disk2.img 와 disk2.img.state.json 입니다.

7.5 수리가 안 될 때

  1. 드라이브를 뽑았다가 다시 꽂고 새로고침을 누른 뒤 다시 해 봅니다. Windows가 디스크를 잠그고 있을 수 있습니다.
  2. 백신이나 탐색기 미리 보기처럼 드라이브를 쓰고 있을 만한 프로그램을 모두 닫습니다.
  3. 그래도 안 되거나, 상태가 계속 Unhealthy 이거나, 드라이브가 나타났다 사라지기를 반복하면 하드웨어 고장일 가능성이 큽니다. 이는 소프트웨어로 고칠 수 없으니 드라이브 교체를 생각해 보세요.

7.6 다시 고장 날 위험 줄이기

드라이브가 다시 고장 나지 않는다고 보장하는 소프트웨어는 없습니다. 건강검진은 드라이브가 스스로 기록해 둔 카운터, 곧 재배치된 섹터, 읽기 오류, 마모도를 읽습니다. 정정할 수 없는 읽기·쓰기 오류가 있거나 마모도가 높으면 다시 고장 날 위험이 크므로 교체를 권합니다.

USB 케이스 중에는 브리지 칩의 한계 때문에 SMART 정보를 넘겨주지 않는 것이 많습니다. 그럴 때 건강검진은 드라이브가 SMART 정보를 제공하지 않는다고 알려 줍니다. CrystalDiskInfo 같은 전용 도구로는 읽힐 수도 있습니다.

기억해 둘 원칙이 몇 가지 있습니다.

  • 소프트웨어는 이미 망가진 셀을 피해서 쓸 뿐입니다. 드라이브의 물리적 수명을 늘리지는 못합니다.
  • 한 번 고장 난 드라이브에 중요한 데이터를 하나뿐인 사본으로 두지 마세요. 늘 백업을 하나 더 두세요.
  • 완전 복구 뒤 얼마 안 가 드라이브가 다시 RAW가 되거나 연결이 자꾸 끊기면 교체하세요.

8. 문제 해결

디스크 목록이 비어 있음

로그에 디스크를 찾지 못했습니다 가 나옵니다. 드라이브가 꽂혀 있는지, Windows 디스크 관리에 보이는지 확인한 뒤 새로고침을 다시 누르세요. USB 드라이브가 아니라면 내장 디스크도 보기(주의)에 체크합니다.

목록에 '펌웨어 고장(ROM 모드)' 또는 '저장 공간 없음(0)'로 나옴

USB의 컨트롤러가 펌웨어를 불러오지 못했거나, 드라이브가 저장 공간을 내주지 않는 상태입니다. Windows에서는 대개 '미디어 없음'이나 0바이트 디스크로 보이고, 포맷하겠느냐고 묻기도 합니다. 그때는 취소를 누르세요. 목록에서 이 드라이브를 고르면 디스크 목록 아래에 진단 상자가 열려 장치 ID, 추정 컨트롤러, 다음에 할 일을 보여 줍니다. 읽을 것도 쓸 것도 없는 상태라 그동안은 백업·복구·수리 버튼이 꺼집니다.

  1. 드라이브를 뽑았다가 다시 꽂습니다. 상자가 5초마다 알아서 다시 확인합니다(다시 확인 단추를 눌러도 됩니다). 원래 이름으로 돌아오면 아무것도 쓰지 말고 먼저 백업하세요. 상자는 열린 채로 돌아왔다고 알려 주고 이미지 백업, 드라이브 시험(빈 공간 전체) 단추를 보여 줍니다. 큰 쓰기를 하다가 다시 멈출 수 있어서, 이 드라이브가 드라이브 시험으로 빈 공간 전체를 통과하기 전까지는 상자를 닫아도 수리와 파일 되돌려 넣기 버튼이 꺼져 있습니다.
  2. 다시 꽂아도 돌아오지 않으면 ReviveUSB로는 살릴 수 없고, 파일도 꺼낼 수 없습니다. 꼭 필요한 파일이라면 데이터 복구 업체가 메모리 칩을 직접 읽어 꺼낼 수도 있습니다. 아니라면 드라이브를 바꾸세요. ReviveUSB는 공장용 도구(양산 툴)를 권하지 않습니다. 우리가 시험한 드라이브에서 통하지 않았고, 공식 배포본도 아닙니다.
  3. 1번에서 돌아왔고 계속 쓰고 싶다면 먼저 백업한 뒤 드라이브 시험 단추로 빈 공간 전체를 시험합니다. 오류 없이 통과하면 그 드라이브의 수리와 파일 되돌려 넣기가 켜지고 상자는 저절로 닫힙니다. 1GB 빠른 시험으로는 켜지지 않습니다.

진단 복사 단추는 상자 내용을 복사합니다. 도움을 청할 때 붙여 넣으세요. 상자는 ×로 닫습니다.

회색 '비어 있음(0)'으로 나오는 장치도 있습니다. 프로그램이 모르는 장치가 저장 공간 0을 알린 경우로, 카드를 꽂지 않은 카드 리더 칸이 흔히 이렇게 보입니다. 고장이 아니니 카드를 꽂으면 됩니다. USB 메모리가 이렇게 나오면 뽑았다가 다시 꽂아 보세요. 읽을 것이 없으니 그동안 백업·복구·수리 버튼은 꺼져 있습니다.

백업이 아주 느림 (예: 예상 시간이 100시간 이상)

프로그램이 이미 불량 구간을 건너뛰므로, 느려지는 원인은 대개 드라이브나 연결 쪽에 있습니다. 처음부터 끝까지 속도가 낮다면(초당 수백 KB) 다음을 차례로 해 보세요.

  1. 드라이브를 PC 뒷면의 USB 3.0 포트(파란색)에 바로 꽂습니다. 허브나 연장 케이블은 피합니다.
  2. 케이블을 바꿉니다.
  3. 다른 PC에서 해 봅니다.

포트를 바꾸려면 ReviveUSB를 닫고 드라이브를 옮겨 꽂은 뒤, 같은 이미지 파일로 다시 백업합니다. 멈춘 곳부터 이어서 진행합니다.

드라이브가 RAW로 보임

Windows는 파일시스템을 읽지 못해도 프로그램은 읽어 내는 경우가 많습니다. 이미지로 백업한 뒤 파일 복구(이름·경로)를 먼저 해 보고, 아무것도 찾지 못하면 파일 복구(시그니처)를 쓰세요. 복구를 마친 뒤 완전 복구(rebuild)로 드라이브를 되살립니다.

"파일시스템을 인식하지 못했습니다"

이름·경로 방식은 NTFS, FAT32, exFAT만 알아보며, 파일시스템 색인을 읽을 수 있어야 합니다. 대신 파일 복구(시그니처)를 쓰세요. (메시지에 carve 나 --fs 같은 명령줄 이름이 나올 수 있는데, 창에서는 시그니처 버튼이 같은 기능입니다.)

"이 작업은 관리자 권한이 필요합니다"

예를 눌러 프로그램을 관리자 권한으로 다시 실행하거나, 프로그램을 닫고 다시 실행하면서 Windows 확인 창에서 허용하세요.

복구한 파일이 열리지 않음

파일이 조각나 저장되어 있어서 앞부분만 복구되었을 수 있습니다. 복구 버튼 두 개를 모두 써 보세요. 드라이브에서 읽지 못한 부분은 이미지에도 빠져 있으므로, 거기 저장된 파일은 온전히 되찾을 수 없습니다.

9. 자주 묻는 질문

Q. USB 드라이브를 살리고 싶은데, "드라이브에 쓰지 말라"는 게 무슨 뜻인가요? A. 드라이브에 새 데이터를 저장하지 말라는 뜻입니다. 백업과 복구는 읽기만 하므로 이 프로그램을 실행하는 것은 괜찮습니다. 2장을 보세요.

Q. 이 프로그램이 원본 드라이브를 망가뜨릴 수 있나요? A. 백업과 복구는 읽기만 합니다. 원본을 바꾸는 것은 수리 버튼뿐이고, 수리 버튼은 먼저 확인을 받습니다.

Q. 파일 이름도 되찾을 수 있나요? A. 파일 복구(이름·경로)는 이름과 폴더를 되살립니다. 파일 복구(시그니처)는 내용만 되살리고 파일 이름은 일련번호로 붙입니다.

Q. 드라이브가 114 GB입니다. 전부 이미지로 떠야 하나요? A. 전체를 백업하는 것이 안전합니다. 시간이 부족하면 중간에 프로그램을 닫고, 그때까지 만든 이미지에 파일 복구(시그니처)를 실행해도 됩니다. 복사된 부분에서 파일을 찾아 줍니다.

Q. 복구가 불가능한 경우도 있나요? A. 있습니다. 데이터가 덮어써졌거나 플래시 칩 자체가 죽었다면 소프트웨어로는 어쩔 수 없습니다. 그때는 전문 데이터 복구 업체에 맡기는 것이 답입니다.

11. 언어

프로그램은 영어로 시작합니다. 언어를 바꾸려면 창 오른쪽 위의 언어 상자에서 고르세요(한국어를 포함해 11개 언어). 프로그램이 이 선택을 기억해 두었다가 다음번에는 그 언어로 시작합니다.

12. 면책 조항

ReviveUSB는 있는 그대로 제공되며 어떠한 보증도 하지 않습니다. 복구가 된다는 보장은 없으며, 수리 버튼은 데이터를 영구히 지웁니다. 프로그램 사용에 따른 책임은 사용자에게 있습니다. 이 프로그램을 쓰다가 생긴 데이터 손실이나 그 밖의 피해에 대해 제작자는 책임지지 않습니다. 중요한 자료는 꼭 백업해 두세요.
