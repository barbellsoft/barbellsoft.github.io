ReviveUSB user manual

ReviveUSB recovers files from a failing USB drive or external hard disk and, when you want, repairs the drive so you can use it again. It all happens in one window: pick a disk, then click a button. Follow this manual from top to bottom.

0. Quick start

  1. Run ReviveUSB.exe and allow administrator rights when Windows asks.
  2. Click Refresh, then click your USB drive in the disk list.
  3. Click Back up to image and save the image on a different drive with enough free space.
  4. Click Recover files (names/paths), pick the image, and choose a folder on a healthy drive. If nothing comes back, do the same with Recover files (signature).
  5. Only when you have all your files, use one of the repair buttons to make the drive usable again.

The one rule that matters: if you want your data back, save nothing new to the broken drive. Make the image first and recover from the image.

If you do not need the data and only want the drive working again, skip steps 3 and 4. Chapter 7 covers this.

1. What the program does

Use it when a drive is in one of these states:

  • You deleted files by accident.
  • Windows asks "You need to format the disk before you can use it" when you plug the drive in. This is a damaged filesystem, shown as RAW.
  • A large drive shows up as a small RAW piece or has no drive letter, because its partition is damaged.
  • The drive is recognized but your files are not visible.

It has two goals, and one tool handles both.

Goal What it means Buttons
Get the data back Recover files that are deleted or invisible Back up to image, then one of the Recover files buttons
Get the drive back Reformat the drive so it can be used again Check (chkdsk), Format, Full rebuild

The order is fixed: recover the data first, repair the drive second. Repairing first destroys the data for good.

2. Safety rules to read before you start

Writing to the broken drive is what ruins recovery. Running this program is fine, because backup and recovery only read from the drive.

Here is why. When you delete a file, the data itself usually stays on the drive. Only the index entry that points to it is removed, and that is why recovery is possible at all. If you then save a new file to the drive, the system sees free space where your old data sits and may write the new file right on top of it. Once that happens the old data cannot be recovered.

Do not do any of these before recovery:

  • Save or copy new files to the drive.
  • Format the drive, either in Windows or with the repair buttons.
  • Click Yes when Windows offers to scan and repair the drive.

These buttons are safe, because they only read: Refresh, Health check, Back up to image, and both Recover files buttons.

broken USB drive --(read only)--> disk2.img (backup copy) --> recovered\ (your files)
   original untouched              work on this copy            results

4. Starting the program

4.1 Download and check the file

Download ReviveUSB.exe from the Download page. The file is not code-signed yet, so Windows SmartScreen or your antivirus may warn you. Before you run it, check that the file matches the SHA-256 shown on the Download page. In PowerShell:

Get-FileHash .\ReviveUSB.exe -Algorithm SHA256

If the hashes match and SmartScreen appears, choose More info, then Run anyway.

4.2 Administrator rights

The program asks for administrator rights when it starts, because reading a raw disk requires them. Allow it. The top of the window then shows Administrator: ON. If it says OFF, click Restart as administrator.

5. Recovering a drive in five steps

Step 1. Select the drive

Plug in the drive and click Refresh. Click your drive in the list. The log confirms which disk you selected, for example Disk 2 selected: SanDisk Ultra.

Look at the Filesystem column. RAW means the filesystem is damaged.

You can click Health check now. It shows the drive's status and, if the drive exposes them, SMART counters such as wear and uncorrectable read errors. Many USB drives do not pass SMART data through; the log then says so.

Step 2. Back up to an image

Click Back up to image. Choose where to save the image, on another drive with enough free space. The suggested name is diskN.img, where N is the disk number.

The original drive is only read. Bad regions are skipped quickly, so the copy keeps going instead of stalling. The progress bar shows the percentage and how much has been copied.

If some regions could not be read, the program asks whether to retry them sector by sector. Retrying can rescue more of your data, but on a badly damaged drive it can take a long time. If you close the window during the retry, back up again to the same file later and it picks up the retry. Backing up again to a finished image never reads the whole drive again: it only offers to retry the unreadable regions. To start over, choose a new file name.

If you pick a place on the drive you are recovering, the program refuses and asks for a different drive. Saving there could overwrite the files you want back.

You can stop at any time by closing the window. Progress is saved every two seconds. To continue, start the program again, select the same drive, click Back up to image, and choose the same file. If Windows asks whether to replace it, answer Yes: the log shows Resuming image and the copy picks up where it left off. The program checks that it is the same drive. If the file belongs to a different drive, or the drive now reports a different size, it stops instead of mixing or overwriting the earlier copy; choose a new file name in that case.

Step 3. Recover files from the image

There are two buttons. Try Recover files (names/paths) first, and use Recover files (signature) if it finds nothing.

  1. Click the button.
  2. Select your image file (.img).
  3. Choose a folder for the recovered files, on a healthy drive. A folder on the drive you are recovering is refused. If the drive has several partitions, each one's files go into its own subfolder such as volume2_exfat.

The names/paths method copies every file it can find, not only deleted ones. That is what you want when Windows says the drive "is not accessible" or asks you to format it: the files are usually still there, and they come back with their names. When it finds both current and deleted files, the deleted ones go into a separate _deleted_files folder so that an old copy never sits next to the current file. The folder you save into needs as much free space as the files; the log warns you before it starts if it does not have it. On a FAT32 drive that Windows deleted files from, the log may list files that "may be wrong inside": Windows erased part of where they start, and for types like .bin there is no signature to tell the right spot. Open those files before you rely on them.

Recover files (names/paths) Recover files (signature)
What you get File names, folder paths, and contents Contents only, named by sequence number such as jpg_00001_@...
Works on NTFS, FAT32, and exFAT Any drive, even when the filesystem is gone
Works best when The filesystem can still be read, even if Windows will not open the drive The filesystem itself is destroyed
Order Try first Use when the first one finds nothing

Try the names/paths method first even if the drive shows as RAW. Windows shows RAW whenever it cannot mount the filesystem, even if only one value in it is wrong, and the program can often still read it and bring the files back with their names. If it says it cannot detect the filesystem, or finds nothing, use the signature method.

The signature method finds JPEG, PNG, GIF, BMP, PDF, and ZIP files, and MP4, MOV, 3GP, M4A, and HEIC files (phone and dashcam videos, iPhone photos). Office files such as docx, xlsx, and pptx are ZIP files inside, so they come back with a .zip name; rename them to the right extension. A video whose end was never written (a cut-off recording, or a drive that lost its data) is saved as far as it goes, but most players cannot play it without the missing end.

If a disk is selected in the list, the program first asks whether to read that disk directly. Click No to choose your image file, or Yes to read the disk itself. Reading the disk needs administrator rights and is riskier for a failing drive, so an image is the better choice.

Step 4. Repair the drive (only after recovery is done)

Select the drive and use one of the repair buttons. Chapter 7 explains which one to pick. Format and Full rebuild erase data, so the program asks you to type a confirmation word exactly, for example FORMAT E. Make sure you have recovered all your files before you use them.

Before Check (chkdsk), Format or Full rebuild writes anything, the program checks the drive by reading only. If the drive shows signs that its controller is failing, it does not repair and says why in the log. The signs are: the drive does not respond to reads or reports a size of 0, or part of the drive could not be read. On FAT32 drives it also checks whether the filesystem claims the drive is bigger than it really is, whether the two copies of the file table (FAT) disagree in many places, and whether half or more of the places that should hold files read back blank. There is no way to force the repair then. Repair writes a lot, and a failing drive can stop working entirely in the middle of a large write. Recover your files with Steps 2 and 3, then replace the drive. A drive that shows as RAW only because its filesystem cannot be recognized is not blocked. The same check runs when you repair without recovering data (chapter 7).

Step 5. Put the files back (after repair)

The full order is: recover the data, keep the recovered files on your PC, repair the drive, then put the files back on the repaired drive. This step is the last part. It also checks that the drive really stores data before you trust it again.

When Format or Full rebuild finishes, the log says: click Refresh, then Test drive, then Copy files back. Both buttons are in the After repair: row and work on the drive letter of the selected disk. They do not need administrator rights.

  1. Click Refresh and select the repaired drive. It may have a new drive letter.
  2. Click Test drive. Choose Yes to test all free space, or No for a quick 1 GB test (Cancel does nothing). The full test is slow, but it is the one that finds drives that fake their capacity. The program writes test data into a _revive_test folder on the drive, reads it back without going through the Windows cache, compares it, and then deletes the folder. A folder left over from an interrupted earlier test is deleted too. If the drive fills up, writing stops there and the data written so far is checked.
  3. Read the result in the log. A pass says how much was written and read back with no errors. A failure says how much did not read back correctly; replace the drive. If data written later came back in place of earlier data, the log says the drive probably holds only about a certain size, less than it claims. That is a drive with fake capacity. Do not put your files on it. If the drive stops responding during the test, the log says after how much data it stopped and that the drive cannot hold data reliably. Do not put your files on it; replace it.
  4. Click Copy files back and select the folder on your PC that holds the recovered files. A folder on the same drive is refused. If the drive does not have enough free space, the program says so before it writes anything. It copies all files with the same folder structure, except top-level System Volume Information and $RECYCLE.BIN folders, which Windows creates again by itself.
  5. After copying, the program reads every file back from the drive, again bypassing the cache, and compares its SHA-256 with the original. If all match, the log says so. If some files did not read back the same, the log lists them and says the drive is not storing data reliably. Do not keep important files on that drive.

Keep the recovered files on your PC even after a successful copy, so you still have a second copy.

7. Repairing a drive when you don't need the data

If you do not need the files and only want a failing USB drive or external disk back in service, skip the backup and recovery steps and repair it directly.

7.1 Diagnose first

Click Refresh, select the drive, and look at the list and the log. A real example from a WD external drive: the list showed 3.6 TB, status Healthy/Online, and only a 200 MB RAW piece without a drive letter.

How to read this: a status of Healthy/Online means the hardware is working and only the partition structure is broken. Software can usually repair that. If a large drive shows only a small RAW piece, or has no drive letter, its main partition is gone.

7.2 Choosing a repair, from gentlest to strongest

Symptom Button What it does
Drive letter exists, files are corrupted or give read errors Check (chkdsk) Fixes filesystem errors and keeps the data
Drive letter exists, you want to wipe it Format Reformats the volume only
RAW, no drive letter, damaged partitions Full rebuild Wipes the whole disk and recreates it. This is the usual fix

Check (chkdsk) and Format need a drive letter. If the drive has none, the program tells you to use Full rebuild instead. chkdsk also cannot repair a RAW drive, because there is no filesystem left to fix.

7.3 Reviving a RAW drive

This is the most common case. Select the drive, click Full rebuild, and type ERASE DISK 2 (with your disk number) when asked. It usually takes a few seconds to a minute. When it finishes, the drive gets a new drive letter. Before you trust it with files, click Refresh, select the drive, and run Test drive. Step 5 in chapter 5 explains the result and how to put your files back.

The new filesystem is NTFS, which Windows reads and writes. If you need the drive on a Mac or another device, reformat it afterwards with that device or with Windows' own format dialog.

7.4 Cleaning up

If you made an image earlier and no longer need it, delete the image file and the progress file next to it, for example disk2.img and disk2.img.state.json.

7.5 If the repair fails

  1. Unplug the drive, plug it back in, click Refresh, and try again. Windows may be holding the disk locked.
  2. Close anything else that might be using the drive, such as antivirus or Explorer previews.
  3. If it still fails, the status stays Unhealthy, or the drive keeps appearing and disappearing, the hardware is probably failing. Software cannot fix that, so consider replacing the drive.

7.6 Lowering the risk of another failure

No software can guarantee a drive will not fail again. Health check reads the counters the drive keeps about itself: reallocated sectors, read errors, and wear. Uncorrectable read or write errors, or high wear, mean a high risk of another failure, and replacement is recommended.

Many USB enclosures do not pass SMART data through, because of limits in the bridge chip. In that case the health check says the drive does not expose SMART data. A dedicated tool such as CrystalDiskInfo may still read it.

Some principles to keep in mind:

  • Software works around cells that have already gone bad. It cannot extend the physical life of the drive.
  • Never keep the only copy of important data on a drive that has failed once. Always keep a second backup.
  • If the drive turns RAW again soon after a rebuild, or keeps disconnecting, replace it.

8. Troubleshooting

The disk list is empty

The log says No disks found. Check that the drive is plugged in and shows up in Windows Disk Management, then click Refresh again. If the drive is not a USB drive, tick Show internal disks (caution).

The list shows "Firmware failure (ROM mode)" or "No storage (size 0)"

The USB's controller could not load its firmware, or the drive reports no storage. Windows usually shows such a drive as "No Media" or as a 0-byte disk, and may ask to format it; choose Cancel. When you select the drive, a Diagnosis box opens below the disk list. It shows the device ID, the likely controller and what to do next. Backup, recovery and repair are turned off while the drive is in this state, because there is nothing to read or write.

  1. Unplug the drive and plug it back in. The box checks again every 5 seconds by itself (you can also click Check again). If the drive comes back with its normal name, do not write to it; back it up first. The box stays open, says the drive is back and shows the Back up to image and Test drive (whole free space) buttons. Repair and Copy files back stay off for this drive until it passes Test drive on the whole free space, even if you close the box, because a large write can make it stop again.
  2. If it does not come back, ReviveUSB cannot revive it, and its files cannot be read. If the files matter, a data recovery lab may be able to read the memory chip directly; otherwise, replace the drive. ReviveUSB does not recommend factory tools (mass production tools): they did not work on the drive we tested, and they are not officially distributed.
  3. If it came back in step 1 and you want to keep using it, back it up first, then run Test drive on the whole free space. When the test passes with no errors, repair and Copy files back turn on for that drive and the box closes by itself. A quick 1 GB test does not turn them on.

Copy diagnosis copies the text in the box so you can paste it when you ask for help. Close the box with ×.

Some devices show "Empty (0)" in gray instead. A device the program does not know is reporting no storage, and an empty card reader slot usually looks exactly like this. That is not a fault: insert a card. If a USB stick shows this, unplug it and plug it back in. Backup, recovery and repair stay off meanwhile, because there is nothing to read.

Backup is very slow (for example, an estimate of 100 hours or more)

The program already skips bad regions, so a slowdown usually comes from the drive or the connection. If the speed is low from start to finish (a few hundred KB/s), try these in order:

  1. Plug the drive straight into a USB 3.0 port (blue) on the back of the PC. Avoid hubs and extension cables.
  2. Swap the cable.
  3. Try another PC.

To switch ports, close ReviveUSB, move the drive, and back up again to the same image file. It continues where it stopped.

The drive shows as RAW

Windows cannot read the filesystem, but the program often still can. Back up to an image and try Recover files (names/paths) first; if it finds nothing, use Recover files (signature). After recovery, bring the drive back with Full rebuild.

"Could not detect the filesystem"

The names/paths method only understands NTFS, FAT32, and exFAT, and it needs the filesystem index to be readable. Use Recover files (signature) instead. (The message may use command-line names such as carve or --fs; in the window, the signature button is the same thing.)

"This action needs administrator rights"

Click Yes to restart the program as administrator, or close it and run it again, allowing the Windows prompt.

Recovered files will not open

The file may have been fragmented, so only its first part was recovered. Try both recovery buttons. Parts of the drive that could not be read are missing from the image, and files stored there cannot come back complete.

9. FAQ

Q. I want to save the USB drive, so what does "don't write to it" mean? A. It means do not save new data to the drive. Running this program is fine because backup and recovery only read. See chapter 2.

Q. Can this damage the original drive? A. Backup and recovery are read-only. Only the repair buttons change the original, and they ask for confirmation first.

Q. Can file names be recovered? A. Recover files (names/paths) restores names and folders. Recover files (signature) restores contents only and names the files by sequence number.

Q. My drive is 114 GB. Do I have to image all of it? A. A full backup is the safe choice. If you are short on time, you can close the program partway and run Recover files (signature) on the image you have so far; it recovers files from the part that was copied.

Q. Are there cases where recovery is impossible? A. Yes. If the data has been overwritten, or the flash chip itself is dead, software cannot help. A professional data recovery service is the answer then.

10. Glossary

Term Meaning
Image (.img) A byte-for-byte copy of the drive in one file. You work on this copy instead of the original
RAW The filesystem index is broken, so Windows cannot read the drive
Signature recovery (carving) Recovering a file by finding its content fingerprint (magic bytes)
Names/paths recovery (undelete) Reading the filesystem index to restore files with their names and paths
Bad sector A storage area that fails to read. Backup skips it and records it
Sector and cluster The smallest unit of storage (usually 512 bytes) and a group of sectors
Administrator rights The Windows permission needed to access a raw disk
