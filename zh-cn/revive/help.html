ReviveUSB 用户手册

ReviveUSB 可以从故障 U 盘或移动硬盘中恢复文件，并在你需要时修复驱动器，使其可以再次使用。所有操作都在一个窗口中完成：选择磁盘，然后点击按钮。请按本手册从头到尾操作。

0. 快速入门

  1. 运行 ReviveUSB.exe，在 Windows 询问时允许管理员权限。
  2. 点击 刷新，然后在磁盘列表中点击你的 U 盘。
  3. 点击 备份为镜像，把镜像保存到另一个剩余空间充足的驱动器上。
  4. 点击 恢复文件（名称/路径），选择镜像，再选择一个位于正常驱动器上的文件夹。如果什么都没找回，用 恢复文件（特征码） 再做一遍。
  5. 只有在拿回全部文件之后，才使用某个修复按钮让驱动器恢复可用。

最重要的一条规则：如果想找回数据，就不要往损坏的驱动器上保存任何新内容。先制作镜像，再从镜像中恢复。

如果你不需要这些数据，只想让驱动器重新能用，可以跳过第 3 步和第 4 步。第 7 章介绍这种情况。

1. 程序的用途

当驱动器处于以下某种状态时使用：

  • 不小心删除了文件。
  • 插入驱动器时，Windows 提示“使用驱动器中的光盘之前需要将其格式化”。这是文件系统损坏，显示为 RAW。
  • 大容量驱动器只显示为一小块 RAW 区域，或没有盘符，因为其分区已损坏。
  • 驱动器能被识别，但看不到你的文件。

它有两个目标，一个工具即可兼顾。

目标 含义 按钮
找回数据 恢复已删除或看不见的文件 备份为镜像，然后使用某个 恢复文件 按钮
找回驱动器 重新格式化驱动器，使其可以再次使用 检查（chkdsk）、格式化、完全重建

顺序是固定的：先恢复数据，再修复驱动器。先修复会让数据永久丢失。

2. 开始之前必读的安全规则

真正毁掉恢复的是向损坏的驱动器写入数据。运行本程序没问题，因为备份和恢复只会读取驱动器。

原因如下。删除文件时，数据本身通常仍留在驱动器上，被删除的只是指向它的索引条目，这正是能够恢复的原因。如果之后再向驱动器保存新文件，系统会把旧数据所在的位置视为空闲空间，并可能把新文件直接写在上面。一旦发生这种情况，旧数据就无法恢复了。

恢复之前，请不要做以下任何一件事：

  • 向驱动器保存或复制新文件。
  • 格式化驱动器，无论是在 Windows 中还是用修复按钮。
  • 在 Windows 提出扫描并修复驱动器时点击“是”。

以下按钮是安全的，因为它们只读取：刷新、健康检查、备份为镜像，以及两个 恢复文件 按钮。

损坏的 U 盘 --(只读)--> disk2.img (备份副本) --> recovered\ (你的文件)

4. 启动程序

4.1 下载并检查文件

从下载页面下载 ReviveUSB.exe。该文件尚未进行代码签名，因此 Windows SmartScreen 或杀毒软件可能会发出警告。运行前，请确认文件与下载页面上显示的 SHA-256 一致。在 PowerShell 中运行：

Get-FileHash .\ReviveUSB.exe -Algorithm SHA256

如果哈希值一致并出现 SmartScreen，请选择 更多信息，然后选择 仍要运行。

4.2 管理员权限

程序启动时会请求管理员权限，因为直接读取原始磁盘需要该权限。请允许。窗口顶部随后会显示 管理员权限：已开启。如果显示未开启，请点击 以管理员身份重新启动。

5. 五步恢复驱动器

第 1 步. 选择驱动器

插入驱动器并点击 刷新。在列表中点击你的驱动器。日志会确认你选择了哪个磁盘，例如 已选择磁盘 2：SanDisk Ultra。

查看 文件系统 列。RAW 表示文件系统已损坏。

此时可以点击 健康检查。它会显示驱动器的状态；如果驱动器提供 SMART 数据，还会显示磨损度、无法纠正的读取错误等计数。很多 U 盘不传递 SMART 数据，这时日志会说明这一点。

第 2 步. 备份为镜像

点击 备份为镜像。选择镜像的保存位置，要在另一个剩余空间充足的驱动器上。建议的文件名是 diskN.img，其中 N 是磁盘编号。

原始驱动器只会被读取。坏区会被快速跳过，因此复制会持续进行而不会卡住。进度条显示百分比和已复制的数据量。

如果有些区域无法读取，程序会询问是否逐扇区重试。重试可以救回更多数据，但在严重损坏的驱动器上可能需要很长时间。如果在重试过程中关闭了窗口，之后再次备份到同一文件即可继续重试。对已完成的镜像再次备份时，绝不会重新读取整个驱动器：只会提供重试无法读取区域的选项。如要从头开始，请选择新的文件名。

如果选择的位置在正在恢复的驱动器上，程序会拒绝并要求选择其他驱动器。保存到那里可能会覆盖你想找回的文件。

你可以随时关闭窗口来停止。进度每两秒保存一次。如要继续，请重新启动程序，选择同一驱动器，点击 备份为镜像，并选择同一文件。如果 Windows 询问是否替换，请回答“是”：日志会显示 继续制作镜像，复制会从中断处继续。程序会检查是否为同一驱动器。如果该文件属于其他驱动器，或驱动器现在报告的大小不同，程序会停止，而不会混合或覆盖之前的副本；这种情况下请选择新的文件名。

第 3 步. 从镜像中恢复文件

有两个按钮。先尝试 恢复文件（名称/路径），如果它什么都没找到，再使用 恢复文件（特征码）。

  1. 点击按钮。
  2. 选择你的镜像文件（.img）。
  3. 在正常驱动器上选择一个存放恢复文件的文件夹。位于正在恢复的驱动器上的文件夹会被拒绝。如果驱动器有多个分区，每个分区的文件会放入各自的子文件夹，例如 volume2_exfat。

名称/路径方式会复制它能找到的所有文件，而不只是已删除的文件。Windows 提示驱动器“无法访问”或要求格式化时，正该用这种方式：文件通常还在，而且会连同文件名一起恢复。如果同时找到现有文件和已删除文件，已删除的文件会放进单独的 _deleted_files 文件夹，这样旧副本不会和现有文件放在一起。保存用的文件夹需要有与这些文件同样多的可用空间；如果空间不够，开始之前日志会发出警告。如果是在 Windows 中删除过文件的 FAT32 驱动器，日志里可能会列出“内容可能不对”的文件：Windows 抹掉了它们起始位置的一部分，而 .bin 这类没有文件签名的格式无法判断正确位置。使用前请先打开检查。

恢复文件（名称/路径） 恢复文件（特征码）
得到的结果 文件名、文件夹路径和内容 只有内容，按序号命名，例如 jpg_00001_@...
适用于 NTFS、FAT32 和 exFAT 任何驱动器，即使文件系统已不存在
最适合的情况 文件系统仍可读取，即使 Windows 打不开该驱动器 文件系统本身已被破坏
顺序 先尝试 第一种什么都没找到时使用

即使驱动器显示为 RAW，也请先尝试名称/路径方式。只要 Windows 无法挂载文件系统，哪怕其中只有一个值出错，它也会显示 RAW；而本程序往往仍能读取，并连同文件名一起恢复文件。如果提示无法识别文件系统，或者什么都没找到，请使用特征码方式。

特征码方式可以找到 JPEG、PNG、GIF、BMP、PDF 和 ZIP 文件，以及 MP4、MOV、3GP、M4A 和 HEIC 文件（手机和行车记录仪的视频、iPhone 照片）。docx、xlsx、pptx 等 Office 文件内部其实是 ZIP 文件，因此恢复后会以 .zip 为扩展名；请把它们改回正确的扩展名。结尾没有写入的视频（录制中途中断，或驱动器丢失了数据）会保存到能读到的位置为止，但缺少结尾时大多数播放器无法播放。

如果在列表中选中了磁盘，程序会先询问是否直接读取该磁盘。点击 否 选择镜像文件，点击 是 直接读取磁盘。直接读取磁盘需要管理员权限，而且对故障驱动器风险更大，因此使用镜像是更好的选择。

第 4 步. 修复驱动器（仅在恢复完成后）

选择驱动器并使用某个修复按钮。第 7 章说明了该选哪一个。格式化 和 完全重建 会清除数据，因此程序会要求你准确输入一个确认词，例如 FORMAT E。使用之前，请确保已经恢复了所有内容。

修复按钮（检查（chkdsk）、格式化、完全重建）在写入驱动器之前，会先只读地检查驱动器。如果出现主控正在损坏的迹象，就不进行修复，并在日志中说明原因。这些迹象是：驱动器不响应读取或容量显示为 0，或者驱动器有部分无法读取。如果是 FAT32 驱动器，还会检查文件系统记录的容量是否大于驱动器实际容量、文件分配表（FAT）的两份副本是否在许多位置不一致、本应存有文件的位置是否有一半以上读出来是空值。此时无法强行修复。修复会大量写入，而正在损坏的驱动器可能在大量写入途中彻底停止工作。请先用第 2、3 步取回文件，再更换驱动器。仅因无法识别文件系统而显示为 RAW 的驱动器不会被拦下。不取回数据直接修复时（第 7 章）也会做同样的检查。

第 5 步. 把文件放回去（修复之后）

完整的顺序是：恢复数据，把恢复的文件保存在电脑上，修复驱动器，再把文件放回修复好的驱动器。这一步就是最后一环。在你重新信任这个驱动器之前，它还会检查驱动器是否真的能保存数据。

格式化 或 完全重建 完成后，日志会提示：点击 刷新，然后点击 测试驱动器，再点击 写回文件。这两个按钮位于 修复后： 这一行，针对所选磁盘的盘符操作，不需要管理员权限。

  1. 点击 刷新 并选择修复好的驱动器。它的盘符可能已经变了。
  2. 点击 测试驱动器。选择“是”测试全部可用空间，选择“否”则快速测试 1 GB（选择“取消”则什么也不做）。完整测试很慢，但只有它能发现虚标容量的驱动器。程序会把测试数据写入驱动器上的 _revive_test 文件夹，绕过 Windows 缓存读回并比较，然后删除该文件夹。之前中断的测试留下的文件夹也会一并删除。如果驱动器写满了，写入就在那里停止，并检查已经写入的数据。
  3. 在日志中查看结果。通过时，日志会说明写入并读回了多少数据，没有错误。失败时，日志会说明有多少数据没能正确读回；请更换这个驱动器。如果后写入的数据出现在先写入数据的位置上，日志会说明该驱动器实际大概只能存放多少，比它声称的少。这是虚标容量的驱动器，不要把文件放到上面。如果测试途中驱动器停止响应，日志会说明处理多少数据后停止，并提示这个驱动器无法可靠地保存数据。不要把文件放到上面，请更换驱动器。
  4. 点击 写回文件，选择电脑上存放恢复文件的文件夹。程序不接受位于同一驱动器上的文件夹。如果驱动器可用空间不足，程序会在写入任何内容之前提示。它会按原来的文件夹结构复制所有内容，但最上层的 System Volume Information 和 $RECYCLE.BIN 文件夹除外，Windows 会自行重新创建它们。
  5. 复制完成后，程序同样绕过缓存，从驱动器读回每个文件，并将其 SHA-256 与原文件比较。如果全部一致，日志会说明。如果有文件读回的内容不同，日志会列出这些文件，并说明该驱动器无法可靠地保存数据。不要在这个驱动器上保存重要文件。

即使复制成功，也请把恢复的文件保留在电脑上，这样你还有第二份副本。

7. 不需要数据时修复驱动器

如果你不需要这些文件，只想让故障 U 盘或移动硬盘重新投入使用，可以跳过备份和恢复步骤，直接修复。

7.1 先诊断

点击 刷新，选择驱动器，然后查看列表和日志。一个 WD 移动硬盘的真实例子：列表显示 3.6 TB，状态为 Healthy/Online，只有一块 200 MB 的 RAW 区域且没有盘符。

如何解读：状态为 Healthy/Online 表示硬件工作正常，只是分区结构损坏。软件通常可以修复。如果大容量驱动器只显示一小块 RAW 区域，或没有盘符，说明其主分区已经没了。

7.2 选择修复方式（由轻到重）

症状 按钮 作用
有盘符，文件损坏或出现读取错误 检查（chkdsk） 修复文件系统错误并保留数据
有盘符，想把它清空 格式化 只重新格式化该卷
RAW、没有盘符、分区损坏 完全重建 清除整个磁盘并重新创建。这是常用的修复方法

检查（chkdsk） 和 格式化 需要盘符。如果驱动器没有盘符，程序会提示你改用 完全重建。chkdsk 也无法修复 RAW 驱动器，因为已经没有可修复的文件系统了。

7.3 救活 RAW 驱动器

这是最常见的情况。选择驱动器，点击 完全重建，在提示时输入 ERASE DISK 2（换成你的磁盘编号）。通常需要几秒到一分钟。完成后，驱动器会获得新的盘符。在把文件放上去之前，请点击 刷新，选择该驱动器，然后运行 测试驱动器。第 5 章的第 5 步说明了如何看结果以及如何把文件放回去。

新的文件系统是 NTFS，Windows 可以读写。如果需要在 Mac 或其他设备上使用该驱动器，之后请用那台设备或 Windows 自带的格式化对话框重新格式化。

7.4 清理

如果之前制作的镜像已不再需要，请删除镜像文件及其旁边的进度文件，例如 disk2.img 和 disk2.img.state.json。

7.5 修复失败时

  1. 拔下驱动器再重新插入，点击 刷新，然后重试。Windows 可能正锁定着该磁盘。
  2. 关闭可能正在使用该驱动器的其他程序，例如杀毒软件或资源管理器的预览。
  3. 如果仍然失败、状态一直是 Unhealthy，或驱动器反复出现又消失，硬件很可能正在损坏。软件无法解决这个问题，请考虑更换驱动器。

7.6 降低再次故障的风险

没有任何软件能保证驱动器不会再次故障。健康检查 会读取驱动器自身记录的计数：重新分配的扇区、读取错误和磨损度。出现无法纠正的读取或写入错误，或磨损度很高，意味着再次故障的风险很高，建议更换。

很多 USB 硬盘盒由于桥接芯片的限制，不会传递 SMART 数据。这时健康检查会提示驱动器不提供 SMART 数据。CrystalDiskInfo 等专用工具也许仍能读取。

需要记住的几条原则：

  • 软件只能绕开已经损坏的存储单元，无法延长驱动器的物理寿命。
  • 切勿把重要数据的唯一副本存放在曾经故障过的驱动器上。务必另做一份备份。
  • 如果驱动器在重建后很快又变成 RAW，或经常断开连接，请更换它。

8. 故障排除

磁盘列表为空

日志显示 未找到磁盘。请确认驱动器已插好，并且在 Windows 的磁盘管理中能看到，然后再次点击 刷新。如果驱动器不是 USB 驱动器，请勾选 显示内置磁盘（慎用）。

列表中显示“固件故障（ROM 模式）”或“无存储空间（0）”

U 盘的主控没能加载固件，或者驱动器不提供存储空间。Windows 通常会把这种驱动器显示为“无媒体”或 0 字节的磁盘，还可能询问是否格式化；此时请选择取消。在列表中选择这个驱动器后，磁盘列表下方会打开 诊断 框，显示设备 ID、推测的主控和下一步操作。这种状态下没有可读写的内容，所以备份、恢复和修复按钮会被关闭。

  1. 拔下驱动器再重新插上。诊断框每 5 秒会自动重新检查（也可以点击 重新检查）。如果它以原来的名称回来，不要写入任何东西，先备份。诊断框会保持打开并提示它已恢复，同时显示 备份为镜像 和 测试驱动器（全部可用空间） 按钮。大量写入可能让它再次停止，所以在这个驱动器通过 测试驱动器（全部空闲空间）之前，即使关闭诊断框，修复和 写回文件 也保持关闭。
  2. 如果重新插上也回不来，ReviveUSB 就无法救活它，也读不出其中的文件。如果文件很重要，数据恢复机构也许能直接读取存储芯片；否则请更换驱动器。ReviveUSB 不推荐工厂工具（量产工具）：它们在我们测试的驱动器上没有成功，而且不是官方发布的。
  3. 如果第 1 步中它回来了，而你还想继续使用，请先备份，再用 测试驱动器 测试全部空闲空间。测试无错误通过后，该驱动器的修复和 写回文件 会开启，诊断框也会自动关闭。1 GB 快速测试不会开启它们。

复制诊断 会复制诊断框的内容，求助时可以粘贴。点击 × 关闭诊断框。

有些设备会以灰色显示“空（0）”。这表示程序不认识的设备报告没有存储空间，没插卡的读卡器插槽通常就是这样。这不是故障，插入存储卡即可。如果 U 盘这样显示，请拔下后重新插入。由于没有可读取的内容，此时备份、恢复和修复按钮都会关闭。

备份非常慢（例如预计需要 100 小时或更久）

程序已经会跳过坏区，因此变慢通常是驱动器或连接造成的。如果速度从头到尾都很低（每秒几百 KB），请按顺序尝试：

  1. 把驱动器直接插到电脑背面的 USB 3.0 接口（蓝色）。避免使用集线器和延长线。
  2. 换一根线。
  3. 换一台电脑。

如要换接口，请关闭 ReviveUSB，移动驱动器，然后再次备份到同一个镜像文件。它会从中断处继续。

驱动器显示为 RAW

Windows 无法读取文件系统，但本程序往往仍能读取。请先备份为镜像，然后先尝试 恢复文件（名称/路径）；如果什么都没找到，再使用 恢复文件（特征码）。恢复之后，用 完全重建 让驱动器恢复可用。

“无法识别文件系统”

名称/路径方式只认识 NTFS、FAT32 和 exFAT，并且需要文件系统索引可读。请改用 恢复文件（特征码）。（消息中可能会出现 carve 或 --fs 等命令行名称；在窗口中，它们就是特征码按钮。）

“此操作需要管理员权限”

点击 是 以管理员身份重新启动程序，或者关闭程序后重新运行，并在 Windows 提示时允许。

恢复的文件打不开

文件可能是分段存储的，所以只恢复了开头部分。请两个恢复按钮都试一试。驱动器中无法读取的部分在镜像里是缺失的，存放在那里的文件无法完整找回。

9. 常见问题

问：我想挽救这个 U 盘，“不要写入”是什么意思？ 答：意思是不要往驱动器上保存新数据。运行本程序没问题，因为备份和恢复只读取。请参阅第 2 章。

问：这会损坏原始驱动器吗？ 答：备份和恢复都是只读的。只有修复按钮会修改原始驱动器，而且会先要求确认。

问：能恢复文件名吗？ 答：恢复文件（名称/路径） 可以还原文件名和文件夹。恢复文件（特征码） 只还原内容，并按序号命名文件。

问：我的驱动器有 114 GB，必须对全部内容制作镜像吗？ 答：完整备份是安全的选择。如果时间紧张，可以中途关闭程序，对目前已有的镜像运行 恢复文件（特征码）；它会从已复制的部分中恢复文件。

问：有没有无法恢复的情况？ 答：有。如果数据已被覆盖，或闪存芯片本身已经损坏，软件就无能为力了。这时只能求助专业的数据恢复服务。

10. 术语表

术语 含义
镜像（.img） 把驱动器逐字节复制到一个文件中。你在这个副本上操作，而不是在原始驱动器上
RAW 文件系统索引已损坏，Windows 无法读取驱动器

坏扇区 无法读取的存储区域。备份时会跳过并记录
扇区与簇 最小存储单位（通常为 512 字节），以及由若干扇区组成的组
